# PWAの機能権限・AI導入

Google Play・課金処理は実装しない。契約状態と機能権限を分離し、現在は家族オーナーの試用切替で確認する。

## 現在の線引き

予定プラン：月500円、1週間無料体験。現在は表示と機能のお試しのみ。決済・契約開始・トライアル日数の消費・自動請求は行わない。

無料：基本記録・履歴・編集・Undo・通常音声・在庫数管理・ホワイトノイズ。有料音源は12秒試聴可能。
有料：背景テーマ、各種ゲージ、在庫切れ予測・通知、家族共有、複数音楽、AIアドバイス、AIへの質問、家族向け今日のまとめ通知。

複雑な自然文をGeminiで解析して育児記録へ変換する「高度AI音声入力」は廃止する。記録入力は通常の音声入力と手動操作を使用し、AIは蓄積済みデータの理解・要約に集中させる。

共通：2人の最後の入眠時刻の遅い方から15分で音楽停止（最後10秒フェード）。片方が起きれば睡眠タイマーを解除。入眠から15分を過ぎた状態では再生を開始しない。音源は独自の合成音で外部音楽API不要。ブラウザがバックグラウンド音声を止める場合は再生継続を保証しない。復帰時に実時刻で期限を再確認する。
共通：睡眠ボタンは保存直後2秒、紫⇔緑のグラデーションとメッセージを表示し再押下を禁止。タブ切替を挟んでも制限を保持。長押し時刻変更とUndoは維持する。

無料への切替ではオーナーだけが共有記録を利用可能。既存メンバーや記録は削除せず、有料へ戻すと再開する。Firestoreの記録読み書き、招待・参加、Wearの記録アクセスもサーバーで制限する。

`functions/ai-policy.js` の機能表をサーバーの唯一の判定元とする。クライアントは返された features を表示と操作の制御に使い、AI callable は同じ判定を毎回実施する。

## AIアドバイス

直近14日間の完了したJST日を7日＋7日に分けて比較し、当日は `todaySoFar` として別扱いする。ミルク、おむつ、離乳食、睡眠、体重、利用可能なメモを集計し、Geminiは「最近の傾向」「今日のポイント」を文章化する。

数値計算はGeminiに任せずTwinly側で行う。同じ日の結果は `families/{familyId}/aiReviews/{YYYY-MM-DD}` にキャッシュし、同日中は再利用する。キャッシュには質問機能で再利用する集計済みコンテキストも保存するが、クライアントへ返すのは文章部分のみ。

## AIに質問

AIアドバイス表示後、その下の入力欄からテキストまたは通常のブラウザ音声認識で質問できる。質問音声そのものはGeminiへ送らず、文字起こしされた質問文を送る。

質問時は次の順で情報を使う。

1. 当日のAIアドバイス
2. AIアドバイス生成時にキャッシュ済みの14日集計
3. 「何時」「直前」「前後」「寝る前」「タイミング」など時系列確認が必要な質問だけ、直近14日分の記録を追加取得

時系列記録は最大200件までに圧縮してGeminiへ渡す。追加調査が不要な質問では生ログを送らない。これにより毎回全履歴を送る方式よりトークン量とFirestore読み取りを抑える。

回答は記録から判断できる範囲に限定し、データにない内容を推測しない。医療診断、治療・投薬指示、具体的な授乳量変更の指示は行わない。

## 今日のまとめ通知

家族オーナーがON/OFFとJSTの通知時刻を設定する。初期表示は21:00。通知対象は、家族に参加中かつTwinlyのWeb Push通知を有効にしている端末。

通知の数値はGeminiを使わずTwinly側で集計する。

- ミルク：合計ml
- 睡眠：当日累計時間。通知時点で睡眠中なら進行中の睡眠も含める
- おむつ：おしっこ・うんち回数
- 詳細日報では離乳食など既存の日次記録も確認できる

スケジューラは15分ごとに実行する。設定時刻以降、当日まだ通知していないPremium家族を対象にするため、設定時刻ちょうどの実行を逃しても同日中に補完する。少なくとも1台へ送信できた時だけ `lastSentDate` を更新し、送信可能な端末がない場合は次の実行で再試行する。

旧 `dailySummaryEmail` 設定が残っていて、新しい `dailySummaryNotification` 設定がまだない家族は、旧ON/OFFと時刻を引き継いで初回Push時に自動移行する。Resend、SMTP、独自送信ドメインは使用しない。

## GitHub設定

- Secret `TWINLY_AI_API_KEY`：Gemini APIキー。`VITE_` を付けない。
- Variable `TWINLY_TRIAL_FAMILY_ID`：試用する既存家族のID。
- Variable `TWINLY_AI_MODEL`：省略時 `gemini-3.6-flash`。generateContent・JSON出力・`thinkingLevel: minimal` 対応のモデルを指定する。
- Web Pushは既存の `TWINLY_WEB_PUSH_PRIVATE_KEY` と公開VAPIDキーを利用する。

ActionsがAI APIキーをGoogle Secret Managerへ渡し、`twinlyAi` だけにバインドする。キーをファイル・CLI引数・ログ・ブラウザへ出さない。

## 費用のガード

Gemini利用は家族単位で1日40回、月600回、5秒間隔。AIアドバイス生成は1日2回まで。成功した呼び出しだけ成功回数へ加算し、プロバイダ障害や設定エラーは成功回数へ加算しない。

AI質問は当日の集計キャッシュを優先して利用する。今日のまとめ通知はGeminiを呼ばないため、毎日の通知自体ではGeminiトークンを消費しない。

## 検証

自動テストで以下を確認する。

- 無料／有料の機能権限
- AIアドバイスの集計・キャッシュ
- AI質問は先に当日アドバイスを必要とすること
- 高レベル質問では時系列ログを追加しないこと
- 時系列質問だけ最大200件のタイムラインを追加すること
- 日次まとめがミルク・排泄・離乳食・進行中睡眠を正しく集計すること
- UIでAI質問と今日のまとめ通知設定が操作できること
